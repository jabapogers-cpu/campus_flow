# 🎓 CampusFlow — Умное бронирование аудиторий

Полнофункциональное решение кейса хакатона **«Бронирование аудиторий университета»**.

**Ключевые особенности:**
- ✅ Все 8 сценариев приёмки реализованы и протестированы
- ✅ Умный конфликт-чек с предложением альтернатив (409)
- ✅ JWT-аутентификация, роли (студент/админ), проверка прав (403)
- ✅ REST API + Swagger UI + интерактивный веб-интерфейс
- ✅ Рекомендации аудиторий по скорингу загрузки
- ✅ Аналитика и статистика для админа
- ✅ CSV-экспорт, очередь на слоты, pytest-тесты
- ✅ Запуск одной командой, Docker Compose, демо-страница

## 📋 API Endpoints

### Аутентификация
- `POST /api/auth/login` — вход, возвращает JWT токен

### Аудитории
- `GET /api/rooms` — список аудиторий с фильтрами (`building`, `minCapacity`, `equipment`)
- `GET /api/rooms/{id}` — карточка аудитории
- `GET /api/rooms/{id}/free-slots?date=YYYY-MM-DD` — свободные слоты на дату
- `GET /api/rooms/recommend/top` — топ-3 рекомендованных аудиторий (бонус)

### Брони
- `POST /api/bookings` — создание брони (409 при конфликте с альтернативами)
- `GET /api/bookings/my` — мои брони
- `DELETE /api/bookings/{id}` — отмена своей брони (403 для чужой)
- `POST /api/bookings/waitlist` — встать в очередь на слот (бонус)
- `GET /api/bookings/waitlist/my` — моя очередь (бонус)

### Админ (требуется роль `admin`)
- `GET /api/admin/bookings` — все брони системы с фильтрами
- `DELETE /api/admin/bookings/{id}` — отмена любой брони
- `POST /api/admin/rooms` — создание аудитории
- `PUT /api/admin/rooms/{id}` — редактирование аудитории
- `DELETE /api/admin/rooms/{id}` — удаление аудитории
- `GET /api/admin/stats/summary` — общая статистика (бонус)
- `GET /api/admin/stats/by-days` — загрузка по дням (бонус)
- `GET /api/admin/stats/by-buildings` — загрузка по корпусам (бонус)
- `GET /api/admin/stats/top-rooms` — топ загруженных аудиторий (бонус)
- `GET /api/admin/export/bookings.csv` — CSV-экспорт броней (бонус)

### Документация
- `GET /docs` — Swagger UI (интерактивная документация API)

## ✅ Сценарии приёмки

Выполняются на seed-данных; даты считаются от дня запуска (завтра = сегодня + 1). Автоматически проверяются в `tests/test_api.py` и на странице `/demo`.

| № | Шаг | Ожидаемый результат |
|---|-----|---------------------|
| 1 | `student1`: `GET /api/rooms?building=B&minCapacity=20&equipment=projector` | 200, только B-101 и B-204 |
| 2 | `student1`: `GET /api/rooms/4/free-slots?date=<завтра>` (roomId=4 — B-101) | 200, слот 14:00–15:00 свободен |
| 3 | `student1`: `POST /api/bookings` {room_id:4, date, start_time:"14:00", end_time:"15:00"} | 201, бронь есть в `GET /api/bookings/my` |
| 4 | `student2`: тот же слот | 409 `BOOKING_CONFLICT` с понятным message и альтернативами (`nearby_slots`, `similar_rooms`) |
| 5 | `student1`: `DELETE /api/bookings/{id}` | 200, слот снова свободен, статус `cancelled` |
| 6 | `student2`: `DELETE /api/bookings/{id}` чужой брони | 403 FORBIDDEN, бронь осталась активной |
| 7 | `admin`: `GET /api/admin/bookings`, `DELETE /api/admin/bookings/{id}` | 200; студенту эти методы дают 403 |
| 8 | Запуск с нуля по README (без файла БД) | приложение стартует, `/docs` открывается, seed загружен |

Формат ошибок FastAPI: `{"detail": {"error": "BOOKING_CONFLICT", "message": "...", "alternatives": {...}}}`.
Админ по матрице прав брони не создаёт (`POST /api/bookings` от admin → 403).

### Очередь ожидания
`POST /api/bookings/waitlist` ставит студента в очередь на занятый слот. Когда бронь отменяют (сам владелец или админ), слот **автоматически бронируется** за первым в очереди (комментарий «Авто-бронь из очереди ожидания»); ответ на отмену содержит `promoted_from_waitlist`.

## 🧪 Тестирование

### Запуск всех тестов

```bash
pytest tests/ -v
```

Тесты используют отдельную временную БД и не затрагивают рабочий `campusflow.db`.

### Юнит-тесты конфликтов

```bash
pytest tests/test_conflicts.py -v
```

Проверяются:
- Пересечение временных интервалов (касание границ НЕ конфликт)
- Валидация времени (мин. 30 минут, макс. 8 часов, рабочие часы 08:00-22:00)

### Интеграционные тесты API

```bash
pytest tests/test_api.py -v
```

Проверяются все 8 сценариев приёмки + health check.

## 🎨 Особенности реализации

### 1. Умный конфликт-чек
Конфликт определяется как пересечение интервалов `[start, end)`, где **касание границ НЕ считается конфликтом**:
- ✅ 10:00-11:00 и 11:00-12:00 — не конфликт
- ❌ 10:00-11:30 и 11:00-12:00 — конфликт

При конфликте система автоматически предлагает:
- **Ближайшие слоты** той же аудитории (±1-2 часа, ±1 день)
- **Похожие аудитории**, свободные в запрошенное время (скоринг по корпусу, вместимости, оборудованию)

### 2. Рекомендации аудиторий (бонус)
`GET /api/rooms/recommend/top` возвращает топ-3 аудитории с учётом:
- Совпадения параметров (корпус, вместимость, оборудование)
- **Загрузка за последние 7 дней** — предлагаем менее загруженные, чтобы не занимать популярные «впустую»
- Доступность в запрошенный слот

### 3. Очередь на слоты (бонус)
Если слот занят, студент может встать в очередь:
```bash
POST /api/bookings/waitlist
```
При отмене брони система уведомляет первого в очереди (`notified=1`).

### 4. Аналитика и статистика (бонус)
Админ видит:
- Загрузку по корпусам (heatmap)
- Загрузку по дням (последние 7 дней)
- Топ-10 самых загруженных аудиторий
- Общую статистику (количество аудиторий, активных броней)

### 5. CSV-экспорт (бонус)
```bash
GET /api/admin/export/bookings.csv?dateFrom=2026-11-01&dateTo=2026-11-30
```

### 6. Демо-страница
`/demo` — автоматический прогон всех 8 сценариев с визуализацией (зелёные галочки).

### 7. Frontend без сборки
Чистый HTML/CSS/JS, тёмная тема, адаптивная вёрстка. Запуск без `npm install`.
